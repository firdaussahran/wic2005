Glossary

Every term with a dotted underline in the notes and labs. Hover over it, focus it with the keyboard, or tap it to see the short definition in place.

ABCDEFGHIJLMNOPRSTUVXY

A

Ansible
An agentless automation tool: playbooks describe the desired state, and modules apply it to devices over SSH or APIs.
API
Application Programming Interface: a defined way for programs to talk to a system — for example, a controller's REST API.
ARP
Address Resolution Protocol: how a host finds the MAC address for an IP address on its local network — it broadcasts a request, and caches the reply.
ASIC
Application-Specific Integrated Circuit: the fixed-function chip that forwards packets in most hardware switches and routers.

B

bearer token
A token sent as Authorization: Bearer <token>. Whoever holds ("bears") it is let in — so it must expire, and travel only over HTTPS.
blast radius
How much of the network one mistake or one compromise can affect. Automation makes it large by default; guardrails make it small.
BMv2
The P4 reference software switch (behavioral model version 2), for running P4 programs without hardware.
BUM traffic
Broadcast, unknown-unicast and multicast traffic: frames a switch or VTEP has to send to every possible destination, because it can't pick just one.

C

cardinality
In a time-series database, the number of distinct series — one for every combination of label values. It drives storage and memory.
CI/CD
Continuous integration and delivery: every change is automatically linted, validated and tested, then deployed in controlled stages.
configuration drift
A difference between what the source of truth says and what a device actually has — from a manual change, a failed run, or a replaced device.
confirmed commit
A NETCONF commit that rolls itself back after a timeout unless a second, confirming commit arrives — protection against changes that cut you off.
Containerlab
A tool that builds lab networks from containers running real network operating systems, described in a YAML topology file.
control plane
The part of a network that decides how traffic should be forwarded — routing protocols or an SDN controller — and fills in the data plane's tables.

D

data plane
The part of a network device that forwards packets, at full speed, using tables it has been given.
datastore
A complete copy of a device's data, conforming to its YANG models: candidate, running, intended or operational.
deparser
The last part of a P4 pipeline: it writes the valid headers back in front of the payload, in a fixed order, to form the outgoing packet.
Docker
A tool for packaging and running software in containers: isolated processes with their own filesystem and network namespace.
DPDK
Data Plane Development Kit: libraries that let a program drive the network card directly from user space, polling for packets instead of going through the kernel — kernel bypass.

E

ECMP
Equal-Cost Multi-Path: spreading traffic over several equally good routes, usually by hashing packet header fields.
EVPN
Ethernet VPN: uses BGP to tell VTEPs which MAC addresses live where, instead of learning them by flooding.

F

FIB
Forwarding Information Base: the table the data plane actually uses to forward packets — the chosen best routes, arranged for fast lookup.
flow table
An OpenFlow switch's list of rules. Each rule matches packet header fields and says what to do with packets that match.

G

Git
A version control system that records every change to a set of files as a commit, so you can see, compare and undo changes.
gNMI
gRPC Network Management Interface: gets, sets and streams YANG-modelled data over gRPC, using protobuf encoding.
gRPC
A framework for calling functions on another machine over HTTP/2, with messages encoded as protobuf. gNMI is built on it.

H

hysteresis
Using two different thresholds to switch on and off, like a thermostat, so that a system doesn't flip back and forth around a single value.

I

idempotency
An operation is idempotent if doing it twice has the same effect as doing it once — essential for automation you may need to re-run.
In-band Network Telemetry
Switches write measurements — such as queue depth and time spent — into the packets they forward, so each packet carries a record of its own journey.

J

Jinja2
A Python templating language, used here to render device configurations from data.
JSON
JavaScript Object Notation: a minimal text format for structured data — objects, arrays, strings, numbers, booleans and null.

L

least privilege
Giving every account, token and system only the access its job needs — no more — so that a compromise does as little damage as possible.
line rate
The full speed of a link. Forwarding at line rate means keeping up with every packet the link can carry, even the smallest ones, back to back.
Linux bridge
A software Ethernet switch built into the Linux kernel. It learns MAC addresses like a hardware switch.
longest-prefix match
How routers choose between overlapping routes: the matching route with the longest prefix — the most specific — wins. A /24 beats a /16.

M

MAC address
The hardware address of a network interface, such as 00:00:00:00:00:01. Ethernet switches forward frames by MAC address.
management plane
How people and tools configure and monitor devices: the CLI, SNMP, NETCONF, APIs and so on.
match–action
The model behind programmable forwarding: look up packet header fields (match), then apply instructions such as forward, drop or rewrite (action).
microburst
A burst of traffic lasting milliseconds to seconds that fills a link and drops packets, yet barely shows in averages over minutes.
Mininet
A tool that emulates a network of hosts, switches and links on one Linux machine, using network namespaces.
MTU
Maximum Transmission Unit: the largest packet an interface can send in one piece — 1500 bytes on standard Ethernet.

N

NETCONF
A network management protocol, usually over SSH, that exchanges YANG-modelled data as XML and supports transactions: candidate datastore, commit and locking.
network namespace
A Linux feature that gives processes their own private network stack: interfaces, addresses and routes. Mininet hosts and containers are built on them.
NFV
Network Functions Virtualisation: running network functions such as firewalls and load balancers as software instead of dedicated appliances.
NMDA
Network Management Datastore Architecture (RFC 8342): separates intended configuration from running configuration and from operational state.
northbound API
The interface between a controller and the applications that use it — usually a REST API.
NPU
Network Processing Unit: a chip with many small programmable cores specialised for packet processing — more flexible than a fixed-function ASIC, usually slower.

O

OAuth 2.0
A framework in which an authorisation server issues access tokens, limited by scopes and lifetime, so clients never need the user's password.
Open vSwitch
A widely used software switch that supports OpenFlow. It's the switch in the Week 4 lab.
OpenAPI
A standard, machine-readable way to describe a REST API — its paths, methods, parameters, schemas and responses — in YAML or JSON. Tools generate documentation, clients and tests from it.
OpenConfig
Vendor-neutral YANG models written by a group of network operators, so that one piece of automation can drive equipment from many vendors.
OpenFlow
A protocol that lets a controller install match–action rules (flows) directly into a switch's flow tables.
overlay
A virtual network built on top of another network (the underlay) by tunnelling, for example with VXLAN.

P

P4
A language for describing how a programmable switch parses and processes packets.
P4Runtime
An API, carried over gRPC, that lets a controller load a compiled P4 program into a switch and write entries into its tables at run time.
packet-in
An OpenFlow message from a switch to its controller carrying a packet the switch doesn't know how to handle.
path MTU discovery
How a sender finds the largest packet that fits the whole path: routers that can't forward a too-big packet send back an ICMP error saying what fits. It fails when nothing is sent back.
PISA
Protocol-Independent Switch Architecture: a programmable parser, a pipeline of match–action stages and a deparser — the model P4 programs target.
protobuf
Protocol Buffers: a compact binary encoding for structured data, defined by a schema. Smaller and faster to parse than JSON or XML.

R

REST
A style of web API: resources identified by URLs, manipulated with standard HTTP methods, with no session state kept on the server.
RESTCONF
An HTTP-based protocol that exposes YANG-modelled data as REST resources, in JSON or XML.
RIB
Routing Information Base: every route the control plane knows about, from all sources, before the best ones are chosen.

S

SDN
Software-Defined Networking: taking the control plane out of individual switches and running it as software, often on a logically centralised controller.
SNMP
Simple Network Management Protocol: the older, polling-based way to read counters and state from devices.
source of truth
The authoritative record of how the network should be — usually data in Git, or a tool such as NetBox. Devices are configured from it, never the other way round.
southbound interface
The interface between a controller and the devices it controls, such as OpenFlow, P4Runtime, NETCONF or gNMI.

T

table-miss
What an OpenFlow switch does with a packet that matches no other rule — set by a priority-0 rule with no match fields, often "send to the controller".
TCAM
Ternary Content-Addressable Memory: hardware that compares a lookup key against every table entry at once, with "don't care" bits. Very fast, but expensive and power-hungry, so tables are small.
threat model
A structured look at a system from an attacker's point of view: what's valuable, how it could be attacked, and what limits the damage.
TTL
Time To Live: a counter in every IP packet that each router decreases by one. At zero the packet is discarded, which stops packets looping forever.

U

underlay
The real IP network that carries tunnelled traffic.

V

veth pair
Two virtual Ethernet interfaces joined back to back: whatever goes in one comes out of the other. They're the "cables" in Mininet and Docker.
VNI
VXLAN Network Identifier: a 24-bit number in the VXLAN header that says which virtual network a frame belongs to.
VTEP
VXLAN Tunnel End Point: the device that wraps frames into VXLAN on one side and unwraps them on the other.
VXLAN
Virtual Extensible LAN: carries Ethernet frames inside UDP packets (port 4789), so a layer-2 network can stretch across a routed IP network.

X

XML
Extensible Markup Language: a tag-based text format for structured data, with schemas and namespaces. NETCONF uses it.

Y

YAML
A human-friendly text format for structured data that uses indentation. Common for configuration files.
YANG
A data modelling language for network configuration and state. NETCONF, RESTCONF and gNMI all carry data structured by YANG models.
