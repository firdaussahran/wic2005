Programmable Networks

A course that moves bottom-up: how a device forwards → how forwarding can be programmed → how devices expose state → how that state is modelled → how models are driven at scale → how the loop is closed → how it’s secured. Fundamentals over applications — mechanisms, abstractions and data models, not vendor product tours.

The weekly rhythm

  1. Pre-class

    60–90 min, self-study

    Exposition: a recorded segment, a reading or a NetAcad module.

  2. Lecture

    60 min, in class

    Consolidation, never new exposition: worked problems, comparisons, misconceptions and Q&A.

  3. Lab

    120 min, hands-on

    15 min briefing, about 100 min building, breaking and diagnosing, 5 min wrap-up.

Course learning outcomes

  1. 01Explain the separation of control, data and management planes, and why that separation enables programmability.
  2. 02Describe the architecture of a programmable forwarding pipeline and express forwarding behaviour as match–action rules.
  3. 03Compare SDN, device-level programmability and configuration automation as distinct approaches, and reason about where each applies.
  4. 04Interpret and construct data models in YANG, and map them to NETCONF, RESTCONF and gNMI operations.
  5. 05Apply REST API fundamentals — resources, verbs, statelessness, authentication, idempotency — to retrieve and modify network state programmatically.
  6. 06Construct small, idempotent automation workflows using version control, templating and a configuration management tool.
  7. 07Evaluate the security and trust implications of an API-driven, centrally controlled network.
  8. 08Reason about failure, consistency and scale in programmable network designs.
